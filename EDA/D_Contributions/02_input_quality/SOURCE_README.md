# PM2.5 데이터 품질 재점검

2026-11-09

입력 자료에서 보완할 사항이 실제로 확인됐습니다. 기존 중국 48개 측정소의 PM2.5=9,985 값은 현재 635노드 DCRNN 학습 입력에도 들어갑니다. 그러나 고농도, 장시간 반복값, 일본 음수를 일괄 삭제하거나 0으로 바꾸는 수정안은 타당하지 않습니다. 전처리를 바꾸면 통계적으로 유의한 개선이 나타난다는 근거도 아직 없습니다.

**이번에는 점검만 수행했습니다. 원본·분석값·모델·공통 채점기·평가 행을 보존했고, 모델을 학습하지 않았습니다.**

## 확인 범위

- 국내 전국 원자료 573곳과 현재 선택된 외부 관측소 514곳, 중구 정답을 구분했습니다. 선택된 514곳은 도시대기 481곳·교외대기 22곳·국가배경 11곳이며 도로변은 없습니다.
- 중국 기존 측정소 48곳, 국경 도시평균 13곳, 신규 동부 도시평균 30곳을 점검했습니다. 현재 DCRNN에는 신규 동부 30곳 중 16곳이 포함돼 중국 입력은 총 77계열입니다.
- 일본 서부 전체 228곳·매칭 후보 188곳·모델 선택 24곳을 구분하고, 동부 18곳도 확인했습니다.
- 몽골 1곳, ASOS 102/108, HYSPLIT 2,559,672행, 특징표 4종을 확인했습니다.
- 실제 DCRNN 635노드 로더를 실행해 학습기간 정규화·입력 결측 마스크·정답 정렬을 확인했습니다. 팀원 A/B/C의 실제 노트북은 이번에 제공되지 않아, 설명에 적힌 대체시간 등의 구현까지 인증한 것은 아닙니다.

## 중국의 극단값과 기존 QC 적용 범위

3578A의 **2021-03-15 16:00 KST=15:00 CST**에 PM2.5=9,985, PM10=1,327이 기록돼 있고 source flag는 0입니다. 보관 원본 CSV와 출처 해시를 대조했으며, 파싱이나 시간 변환이 새로 만든 값은 아닙니다. 물질 간 극심한 불일치와 전후 관측을 고려하면 강한 오류 의심값이지만, 기기 고장 원인까지 확정한 것은 아닙니다.

기존 QC는 신규 동부 30개 도시평균에서 PM2.5 3셀과 PM10 1셀을 격리한 정책입니다. 기존 중국 48개 측정소 전체에 적용된 것은 아니어서 9,985 값이 남았습니다. 실제 DCRNN에서 정규화된 입력은 약 6.27이고, 학습 도착시점 16개의 48시간 입력 창에 포함됩니다. 이 셀을 제외했을 때 정규화 통계만 계산했으며, 재학습하지 않았으므로 예측 결과가 얼마나 바뀌는지는 알 수 없습니다.

## 반복값·PM2.5/PM10 역전·고농도

중국 48곳에서 같은 값이 연속 24시점 이상 나타난 120구간, 3,741시간을 재현했습니다. **그중 3,493시간은 농도 3**입니다. 검출하한·정수 반올림·공급원 처리와 센서 고장을 구분해야 하므로 모두 고장으로 확정할 수 없습니다. 연속 24개 시간 관측은 시작~종료 간 23시간입니다. 실제 경과시간 24시간 이상이라는 다른 정의를 쓰면 3,213시간으로 달라집니다.

2230A에서 PM2.5=48과 PM10=53이 함께 고정된 56시간 구간은 우선 확인할 후보입니다. 국내 514곳+중구에도 403개 반복구간, 14,304시간이 있습니다. 반복을 나중에 발견하고 초반부터 전 구간을 소급 제거하면, 예측 당시에는 몰랐던 미래 정보가 QC 판정에 들어갑니다. 운영 목적의 규칙은 해당 시점까지의 정보로 판정해야 합니다.

PM2.5가 PM10보다 조금 큰 모든 값을 삭제하는 규칙도 권하지 않습니다. 이 조건은 중국 48곳에서 50,746셀, 기존 국내 34곳에서 21,018셀에 해당합니다. 측정 오차·측정법 차이·PM10 쪽 오류 가능성까지 확인해야 합니다.

중국 48곳의 PM2.5>500은 287셀입니다. 중국 현지 설날 4일에는 144셀, 한국 날짜를 쓰면 154셀이 포함됩니다. 2024-02-10의 105셀은 한국 날짜 기준이며 중국 날짜로는 94셀입니다. 날짜 일치만으로 불꽃놀이를 원인으로 확정하거나 모든 500 초과값을 오류로 취급하지 않습니다. 신규 도시 QC의 급등 규칙을 기존 48곳에 그대로 확장하면 27셀 중 설날 7셀도 걸려 실제 사건 훼손 가능성을 검토해야 합니다.

중국 CO=90 mg/m3 4셀도 단위·제공자 상태 확인 후보로 남겼습니다. 현재 DCRNN은 PM2.5만 노드 농도 입력으로 쓰므로 이 CO 값이 DCRNN에 입력된 것은 아닙니다. 국내 최대 803은 울진 437421의 2022-03-07 09시이며, 전후도 고농도입니다. 원측정·PM10·주변 자료 확인 없이 상한만으로 삭제하면 안 됩니다.

## 일본 음수

전체 서부 228곳의 음수 181,286개·최대 506과 현재 모델 서부 24곳의 음수 10,551개·최대 176은 다른 모집단입니다. 현재 동부 18곳에는 음수 18,989개가 있고 최대값은 404입니다. 음수 원값은 `pm25_negative_raw`와 flag 5에 보존돼 있습니다.

일본 환경성은 유효한 작은 음수 시간값을 원칙적으로 유지하며, 0으로 강제 변경하는 것도 평균을 위로 치우치게 할 수 있다고 설명합니다. 현재의 음수→결측 정책 역시 관측 평균을 바꿉니다. 모델 서부 24곳의 단순 평균은 부호 있는 원값 9.6015 / 0 치환 9.6417 / 현재 결측 처리 9.7663입니다. 이는 예측 성능 차이의 증명이 아닙니다. 작은 음수와 -50 같은 큰 음수는 구분해야 합니다.

`log1p`는 -1 이하를 그대로 받을 수 없으므로 부호 있는 관측을 복원하려면 원측정 QC와 입력 변환을 함께 정의한 별도 전처리 버전이 필요합니다. 이번에는 어느 값도 바꾸지 않았습니다. NIES 공식 결측 코드는 양수 9999/9998/9997이고, 보존된 음수에 -999/-9999 같은 코드를 실제 농도로 섞은 문제는 확인되지 않았습니다. 일본 원본 ZIP은 로컬에서 확인하지 못해, 보존된 음수 원값과 공식 형식을 대조한 범위의 점검입니다.

## 정답 결측과 기상

서울 중구 전체 결측은 1,545/35,064시간이며, 2023년에는 1,164/8,760시간입니다. 가장 긴 공백은 **2023-01-09 12:00~2023-02-22 20:00 KST**, 1,065개 시간 관측입니다. 빠진 시간 관측의 개수로 44일 9시간에 해당합니다. 겨울철·고농도 평가의 대표성과 검정력이 제한됩니다. 정답을 보간하거나 다른 측정소 값으로 대체해 점수화하지 않습니다.

몽골의 2023년 결측은 82.386%여서, '효과가 없다'보다 '평가할 관측이 부족하다'는 해석이 필요합니다. ASOS에서 기존 물리범위/QC 규칙 위반과 flag-분석값 모순은 확인되지 않았습니다. 강수 공란 약 89.1%는 보고 특성을 확인해야 하므로 모두 무강수 0으로 바꾸지 않습니다. 풍향 0+양의 풍속 1,253행은 북풍으로 오해하지 않도록 u/v 결측과 방향 불명 표시로 처리됩니다.

## 파이프라인 검증과 한계

HYSPLIT의 좌표·시간·u/v-풍속 대조에서 불일치가 없었고, 음수 강수·잘못된 위도경도·습도 범위 위반도 확인되지 않았습니다. 실제 DCRNN은 2021~2022년으로만 정규화하고, 결측은 정규화 값 0+결측 채널 1로 처리합니다. 3/6/12/24시간 정답과 원관측, 정답시각, 고정 평가 행 `eligible`이 모두 일치했습니다.

특징표는 Parquet 메타데이터로 결측·무한값을 점검했으며 모든 파생변수를 재계산한 검사는 아닙니다. v3의 전 기간 결측 경로 열 28개 등은 후보 라이브러리의 가용성 문제입니다. 추가 국내 이력표의 전 결측 측정소 437371은 현재 선정된 514곳/DCRNN 노드에 포함되지 않습니다. 표의 `above500/above1000` 열은 PM 농도 검토용이며 기압 등 다른 단위 변수의 오류 기준이 아닙니다.

보고서의 `passed/completed`는 검사 실행 성공을 뜻하며 모든 측정값의 무결점 인증이 아닙니다. 현재 로컬 프로젝트 기준 점검으로 팀원의 다른 PC/Colab 파일은 별도 해시 대조가 필요합니다.

## 권장 후속 처리

1. 9,985처럼 불일치가 큰 값부터 원값·출처·QC flag를 보존하는 새 분석 버전에서 격리합니다.
2. 반복값과 급등은 검토표로 남기고, 현재/과거 정보만 쓰는 판정과 실제 고농도 보존을 확인합니다.
3. 일본 음수는 일괄 0 치환하지 않고 공식 지침·원측정 유효성·log1p 호환성을 함께 검토합니다.
4. QC 정책을 모델 성능과 독립적으로 고정한 뒤, 같은 평가 행에서 원버전과 새 버전을 비교합니다.
5. 자료나 정규화가 바뀌면 기존 체크포인트 재개가 아니라 별도 데이터 버전·학습으로 관리합니다.
