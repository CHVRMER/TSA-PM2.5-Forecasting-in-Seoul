Graph WaveNet M1~M4T: Vast.ai 실행 안내
2026-11-10 / 실제 유료 인스턴스·Google OAuth 인증·Drive 전송은 이 문서 작성 과정에서 실행하지 않았습니다.

1. 실행 서버와 데이터
Vast에서 PyTorch CUDA 환경의 단일 GPU 인스턴스를 준비합니다. 현재 제시된 호스트의 가격·계약 lifetime·디스크·RAM·전송 비용을 확인합니다.
RTX 5090은 오래된 CUDA 12.1/12.6 PyTorch 이미지와 맞지 않을 수 있습니다. 현재 PyTorch 2.12 안내는 Blackwell에 CUDA 13.0+ 바이너리를 사용하며 Linux 드라이버 580.65.06 이상을 요구합니다.
setup은 기존 PyTorch를 임의 재설치하지 않고 실제 GPU 연산까지 점검합니다. torch.cuda.is_available()만 확인하고 full을 시작하지 않습니다.

기존 데이터 패키지 TSA_GraphWaveNet_Runpod_M1_M4T_20261110.zip을 재사용합니다. 여기에 Dataset/와 공통 코드가 있습니다.
새 작은 패키지 TSA_GraphWaveNet_VastAI_M1_M4T_20261110.zip은 Dataset을 중복 포함하지 않는 추가 코드입니다.
Runpod용 기존 코드·DCRNN 결과는 유지하고 Vast 실험은 새 위치에 둡니다.

2. 업로드와 압축해제
Vast Connect에 나온 SSH 사용자·호스트·포트를 그대로 사용합니다. 아래 root@SERVER_IP와 SSH_PORT는 실제 값으로 바꿉니다.

내 PC Git Bash 예시:
scp -P SSH_PORT -i ~/.ssh/id_ed25519 "/c/경로/TSA_GraphWaveNet_Runpod_M1_M4T_20261110.zip" root@SERVER_IP:/workspace/
scp -P SSH_PORT -i ~/.ssh/id_ed25519 "/c/경로/TSA_GraphWaveNet_VastAI_M1_M4T_20261110.zip" root@SERVER_IP:/workspace/

서버의 Jupyter 업로드를 사용해도 됩니다. 설치 전에는 개인키·Google 인증 파일을 프로젝트 ZIP에 넣지 않습니다.
새 서버에서는 기존 큰 ZIP의 최상위 Dataset/와 Model/이 /workspace/TSA 안에 오도록 풉니다. 작은 ZIP은 같은 TSA 루트에 풀어 새 VastAI 폴더를 추가합니다.
이미 정상 Dataset이 있다면 큰 ZIP을 다시 풀 필요는 없습니다. 기존 데이터나 결과를 삭제하지 않습니다.

최종 구조:
/workspace/TSA/
  Dataset/
  Model/Common/
  Model/DCRNN/Graph_WaveNet/
    Runpod_M1_M4T_20261110/      기존 코드 유지
    VastAI_M1_M4T_20261110/      이번 코드
      Codes/
      configs/default.json
      setup_vast.sh
      run_pilot.sh
      run_full.sh
      GOOGLE_DRIVE_BACKUP.md
  Environment/GraphWaveNet_VastAI/
  Result/GraphWaveNet/VastAI/    매 실행 새 결과 폴더

프로젝트가 다른 위치라면 export TSA_PROJECT_ROOT=/실제/루트 로 설정합니다.
Vast Local Volume을 /data에 연결했다면 /data/TSA처럼 그 안에 프로젝트를 두고 TSA_PROJECT_ROOT를 맞출 수 있습니다.
일반 /workspace 경로 자체가 인스턴스 삭제 후에도 남는다는 뜻은 아닙니다. mount 구성을 확인합니다.

3. 환경과 pilot
cd /workspace/TSA/Model/DCRNN/Graph_WaveNet/VastAI_M1_M4T_20261110
bash setup_vast.sh
bash run_pilot.sh

pilot은 데이터 연결·전처리·GPU 학습·추론의 동작 확인입니다. 고정 평가 행 전체를 사용하지 않으므로 공식 공통 채점 결과로 해석하지 않습니다.
pilot이 끝나면 메모리와 조건당 시간을 보고 full의 batch size 등 실행 설정을 고릅니다. 설정을 바꾸면 같은 실험 재개로 무조건 취급할 수 없습니다.

4. Google Drive 연결 (full 전에 필수)
GOOGLE_DRIVE_BACKUP.md의 절차대로 rclone의 gdrive 연결을 준비합니다. 아직 자동으로 연결된 상태가 아닙니다.
2026년 rclone 문서는 공용 client_id 중단으로 own Google OAuth client_id 사용을 요구합니다.
인증은 본인 PC 브라우저에서 진행합니다. refresh token과 client_secret은 채팅에 보내지 않습니다.
서버 전용 설정 파일의 예:
export RCLONE_CONFIG="$HOME/.config/rclone/tsa-vast.conf"
chmod 600 "$RCLONE_CONFIG"

백업 위치:
gdrive:Colab_Notebooks/TSA/Result/GraphWaveNet/VastAI

쓰기·검증 확인까지 완료해야 합니다. 연결이 준비되지 않은 full 실행은 사전 점검에서 중단합니다.
Drive의 이전 실행 폴더를 지우는 sync 대신 copy와 check를 사용합니다. 백업 실패 로그를 성공으로 해석하지 않습니다.

5. full 검증부터
bash run_full.sh

기본은 6조건 M1,M2,M3,M4,M3T,M4T, seed11, 2023 검증입니다. full은 공통 채점을 실행합니다.
2024 최종 시험은 선택을 마친 뒤 --final-test를 명시할 때만 엽니다:
bash run_full.sh --final-test

M1: 국내 관측 기준선
M2: M1 + 가까운 중국
M3: 국내 + 선정된 중국 전체
M4: M3 + 일본·몽골
M3T/M4T: 해당 국가 범위에 맞춘 궤적 특징 추가
일본·몽골이 반드시 무익해야 한다고 가정하지 않습니다. 실제 검증 결과로 판단합니다.

서버에는 매 epoch 재개용 last·이전 상태(prev)와 best가 저장됩니다.
epoch1·5·10·15·… 및 종료 시 스냅샷·결과를 Google Drive에 복사하고 검사합니다.
각 조건이 끝나면 추론·채점 결과를 확인할 수 있으며 다음 조건이 실행 중이어도 완료본은 보존됩니다.
새 실행은 새 서버 폴더와 새 Drive 폴더를 사용합니다. 같은 실행 안의 last/best는 의도적으로 갱신됩니다.

6. 접속을 끊어도 학습 유지
권장:
tmux new -s gwn_vast
export RCLONE_CONFIG="$HOME/.config/rclone/tsa-vast.conf"
bash run_full.sh

Ctrl+B 다음 D로 분리하고, 재접속 후 tmux attach -t gwn_vast 로 돌아옵니다.
tmux는 SSH 단절에 대비할 뿐 인스턴스 정지·삭제·호스트 장애를 막지 않습니다.
서버 결과 로그에서 epoch 진행, 현재 입력조건, 검증 점수, 체크포인트 경로, Drive 백업 검증 성공 여부를 확인합니다.

7. 중단 후 재개
서버가 살아 있고 결과가 남아 있다면:
bash run_full.sh --resume-source /workspace/TSA/Result/GraphWaveNet/VastAI/실제_이전_batch_root

다른 서버라면 GOOGLE_DRIVE_BACKUP.md의 복구 절차대로 이전 Drive 백업을 새 로컬 폴더에 복원한 뒤 --resume-source로 지정합니다.
Launch 로그 폴더가 아니라 학습 batch root를 지정합니다. 재개 시도도 새 출력 폴더를 만들고 기존 결과는 보존합니다.
호스트가 사라지면 마지막 외부 백업 성공 이후의 진행분은 복구되지 않을 수 있습니다. 서버 last를 매번 저장한다는 사실만으로 외부 백업까지 최신인 것은 아닙니다.

8. 저장소 수명과 종료
Vast도 Stop/Restart 때 기본 디스크 데이터가 유지됩니다. 저장소 비용은 계속되고 재시작할 GPU 확보는 별도입니다.
Destroy는 기본 디스크 데이터를 삭제합니다. 별도 Local Volume은 남아도 같은 호스트에만 연결됩니다.
계약 lifetime이 만료되면 재시작할 수 없고 이후 삭제될 수 있으므로 만료 전에 Drive 백업을 확인합니다.
이 코드가 학습 후 유료 인스턴스를 자동 중지·삭제한다고 가정하지 마세요. 결과와 백업을 확인한 뒤 직접 Stop/Destroy 여부를 결정합니다.
